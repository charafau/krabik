# krabik-ui-android

Declarative Android view bindings for Rust, created through direct JNI.

`krabik-ui-android` turns a plain Rust element tree into real Android framework views. It contains
no application screens, navigation, or Java-specific JNI entry points, so it can be reused by any
Android app that wants to build its UI from Rust.

The [`example/`](example/) directory is a complete Android app that consumes this crate. It is also
the integration reference for adding the library to a project generated by
[krabik](https://github.com/charafau/krabik).

## Scope

- Declarative layout primitives: `Scroll`, `Linear`, `Recycler`, `ViewPager`, `RadioGroup`, and
  `Placed` children.
- Components for 25 framework widgets, from `TextView` and `Button` to `Toolbar`, `SearchView`, and
  `CalendarView`, plus AndroidX `RecyclerView`, `ViewPager2`, and `AppCompatToolbar`.
- Broad Material Components coverage: buttons, chips, cards, text fields, app bars, FABs, progress,
  sliders, tabs, navigation, carousels, and Material dialogs/snackbars/date and time pickers.
- A `Renderer` that instantiates each widget with its `(Context)` constructor, applies properties,
  and attaches it with the correct `LayoutParams`.
- Fallible JNI helpers, error reporting, framework constants, and AndroidX layout-manager helpers.

Application concerns such as navigation, state, and click semantics stay in the consuming crate.

## Usage

```rust
use krabik_ui_android::ui::{
    Button, EdgeInsets, Element, Length, Linear, Metrics, Orientation, Placed, Text,
};
use krabik_ui_android::Renderer;

fn screen() -> Element {
    Element::Linear(Linear {
        orientation: Orientation::Vertical,
        padding: EdgeInsets::all(16.0),
        background: None,
        children: vec![
            Placed::new(Text::new("Hello from Rust")),
            Placed::new(Button::new("Continue").action("continue"))
                .width(Length::MatchParent)
                .height(Length::Dp(48.0))
                .margins(EdgeInsets::top(8.0)),
        ],
    })
}

// `env` is a `jni::Env`, `activity` is an `android.app.Activity`, and `listener` is a
// `View.OnClickListener` implemented by the app's bridge.
let tree = screen();
let metrics = Metrics::from_context(env, activity)?;
let mut renderer = Renderer::new(env, activity, listener, metrics);
let root = renderer.render(&tree)?;
```

`Button::action(tag)` writes the tag onto the button. When the button is clicked, the
application's `OnClickListener` receives the view and can read the tag with `View.getTag()`.

## Using it from a krabik project

The crate is consumed as a local path dependency for now. Check out this repository next to your
generated project:

```text
projects/
├── krabik/                  # this repository
└── my-app/                  # generated by `krabik create my-app`
```

Add the dependency to the krabik project's `my-app/rust/Cargo.toml`:

```toml
[dependencies]
krabik-ui-android = { path = "../../krabik/packages/krabik-ui-android" }
```

Once the crate is published, a version or git dependency can be used instead.

Then add a small Android bridge and the Rust entry points. These are application concerns and live
in the app, not in the library. The quickest way to start is to copy the pieces from the example and
rename the package-specific parts:

1. **Android bridge** — copy
   `example/android/app/src/main/java/com/example/krabik_ui_example/AndroidBridge.java` into the
   krabik project's `android/app/src/main/java/<your/package>/` and update its `package` line.
   `MainActivity` shows the matching lifecycle and back handling.
2. **JNI entry points** — copy the pattern from `example/rust/src/android/ffi.rs` into the app crate.
   The exported function names must match the bridge's Java package. JNI escapes `_` in package
   names as `_1`, so the example package `com.example.krabik_ui_example` becomes:

   ```text
   Java_com_example_krabik_1ui_1example_AndroidBridge_nativeCreateUi
   Java_com_example_krabik_1ui_1example_AndroidBridge_nativeOnClick
   Java_com_example_krabik_1ui_1example_AndroidBridge_nativeBack
   Java_com_example_krabik_1ui_1example_AndroidBridge_nativeDestroyUi
   ```

3. **State and rendering** — `example/rust/src/android/mod.rs` shows the minimal `UiState` that
   retains the activity/listener global references, builds an `Element` tree, and calls
   `Renderer::render` followed by `Activity.setContentView`.
4. **RecyclerView / ViewPager2 only** — copy `example/rust/src/android/adapter.rs` and
   `TextRecyclerAdapter.java`, then update the class name passed to `jni_str!`.

`example/rust/Cargo.toml` and `example/android/app/build.gradle.kts` show how the native library is
built and staged into `jniLibs`.

### Gradle dependencies

Framework widgets need no extra dependencies. Add these only when using the corresponding
components:

```kotlin
implementation("androidx.appcompat:appcompat:1.7.1")       // AppCompatToolbar
implementation("androidx.recyclerview:recyclerview:1.4.0") // Recycler
implementation("androidx.viewpager2:viewpager2:1.1.0")     // ViewPager
implementation("com.google.android.material:material:1.14.0") // Material components
```

`AppCompatToolbar` also needs a `Theme.AppCompat` variant in the app theme. Material components need
a Material Components theme, for example `Theme.Material3.DayNight.NoActionBar`. To use the
Material date and time pickers, the host activity must be a `FragmentActivity` or
`AppCompatActivity`.

## Supported widgets

`TextView`, `Button`, `EditText`, `ImageView`, `ImageButton`, `CheckBox`, `RadioButton`, `Switch`,
`ToggleButton`, `CheckedTextView`, `ProgressBar`, `SeekBar`, `RatingBar`, `Spinner`,
`AutoCompleteTextView`, `MultiAutoCompleteTextView`, `NumberPicker`, `DatePicker`, `TimePicker`,
`Chronometer`, `TextClock`, `CalendarView`, `AnalogClock`, `SearchView`, `Toolbar`,
`AppCompatToolbar`, `RecyclerView`, and `ViewPager2`.

Material components: `MaterialText`, `MaterialButton`, `MaterialButtonToggleGroup`,
`MaterialCheckBox`, `MaterialRadioGroup`, `MaterialSwitch`, `MaterialTextField`, `MaterialDropdown`,
`MaterialSearchBar`, `MaterialSearchView`, `MaterialChip`, `MaterialChipGroup`, `MaterialCard`,
`MaterialToolbar`, `MaterialAppBar`, `MaterialCollapsingToolbar`, `MaterialBottomAppBar`,
`MaterialToolbarLayout` (floating and docked toolbars), `MaterialFab`, `MaterialExtendedFab`,
`MaterialProgress`, `MaterialLoading`, `MaterialSlider`, `MaterialDivider`,
`MaterialShapeableImage`, `MaterialTabs`, `MaterialBottomNavigation`, `MaterialNavigationRail`,
`MaterialNavigation`, and `MaterialCarousel`.

### LinearLayout

`Linear` renders an `android.widget.LinearLayout`. Containers nest freely, so a row inside a column
is just a horizontal `Linear` inside a vertical one:

```rust
use krabik_ui_android::ui::{EdgeInsets, Length, Linear, Orientation, Placed, Text};

let row = Linear {
    orientation: Orientation::Horizontal,
    padding: EdgeInsets::all(8.0),
    background: None,
    children: vec![
        Placed::new(Text::new("One")).width(Length::Dp(64.0)),
        Placed::new(Text::new("Two"))
            .width(Length::Dp(64.0))
            .margins(EdgeInsets::right(8.0)),
    ],
};

let screen = Linear {
    orientation: Orientation::Vertical,
    padding: EdgeInsets::all(16.0),
    background: None,
    children: vec![Placed::new(row).width(Length::MatchParent)],
};
```

### AppCompat Toolbar

`AppCompatToolbar` renders `androidx.appcompat.widget.Toolbar` and accepts the same title,
subtitle, background, and navigation icon as the framework `Toolbar`:

```rust
use krabik_ui_android::constants::{COLOR_WIDGETS_BACKGROUND, DRAWABLE_MENU_REVERT};
use krabik_ui_android::ui::{AppCompatToolbar, Length, Placed};

let toolbar = Placed::new(AppCompatToolbar {
    title: "AppCompat Toolbar",
    subtitle: "Built from Rust",
    background: COLOR_WIDGETS_BACKGROUND,
    navigation_icon: DRAWABLE_MENU_REVERT,
})
.width(Length::MatchParent)
.height(Length::Dp(72.0));
```

The renderer applies title and subtitle colours, a navigation icon and content description, and two
overflow menu items.

### Material Components

Material widgets are regular elements in the same tree. They are created by class name, so the crate
does not depend on the Material Gradle artifact:

```rust
use krabik_ui_android::ui::{
    Length, MaterialBoxMode, MaterialButton, MaterialCard, MaterialText, MaterialTextField, Placed,
};

let card = MaterialCard::new(vec![
    Placed::new(MaterialText::new("Card title").size(18.0)),
    Placed::new(
        MaterialTextField::new("Email")
            .helper_text("We never share your address.")
            .box_mode(MaterialBoxMode::Outlined),
    )
    .width(Length::MatchParent),
    Placed::new(MaterialButton::new("Save").action("save"))
        .width(Length::MatchParent)
        .height(Length::Dp(48.0)),
])
.radius(16.0)
.elevation(4.0);
```

Menus for `MaterialToolbar`, `MaterialBottomNavigation`, `MaterialNavigationRail`, and
`MaterialNavigation` are created from Rust with `Menu.add()`. `MaterialCarousel` uses the same
`RecyclerView.Adapter` factory as `Recycler` and `ViewPager`.

Some Material features are actions rather than views. They live in `krabik_ui_android::material`:

```rust
use krabik_ui_android::material;

material::show_snackbar(env, &root, "Saved", false)?;
material::show_alert_dialog(env, activity, "Delete item?", "This cannot be undone.")?;
material::show_date_picker(env, activity, "Pick a date")?;
material::show_time_picker(env, activity, "Pick a time")?;
material::attach_badge(env, activity, &fab, 3)?;
material::apply_dynamic_colors(env, activity)?;
material::set_tooltip(env, &view, "Refresh")?;
```

The dialog and picker helpers require a Material Components theme; the pickers also require an
`AppCompatActivity` for its support `FragmentManager`.

### RecyclerView and ViewPager2

Both AndroidX widgets draw through an abstract `RecyclerView.Adapter`, so the application has to
provide a small concrete adapter class. Register a factory that constructs it:

```rust
use krabik_ui_android::views::ItemAdapterFactory;

struct MyAdapterFactory;

impl ItemAdapterFactory for MyAdapterFactory {
    fn create_adapter<'local>(
        &self,
        env: &mut jni::Env<'local>,
        context: &jni::objects::JObject<'_>,
        items: &[&str],
        sizing: krabik_ui_android::views::AdapterItemSizing,
    ) -> krabik_ui_android::Result<jni::objects::JObject<'local>> {
        // Build a String[] and construct `MyTextAdapter(Context, String[], boolean)`.
        let items = krabik_ui_android::views::new_string_array(env, items)?;
        krabik_ui_android::env::EnvExt::construct(
            env,
            jni::jni_str!("com/example/MyTextAdapter"),
            jni::jni_sig!("(Landroid/content/Context;[Ljava/lang/String;Z)V"),
            &[
                jni::objects::JValue::Object(context),
                jni::objects::JValue::Object(&items),
                jni::objects::JValue::Bool(matches!(
                    sizing,
                    krabik_ui_android::views::AdapterItemSizing::FillParent
                )),
            ],
        )
    }
}

let mut renderer = Renderer::new(env, activity, listener, metrics)
    .with_item_adapter_factory(&MyAdapterFactory);
```

Once the factory is registered, put either widget in the tree like any other component:

```rust
use krabik_ui_android::ui::{Length, Placed, Recycler, ViewPager};

let items = &["Alpha", "Bravo", "Charlie", "Delta"];

let list = Placed::new(Recycler::new(items))
    .width(Length::MatchParent)
    .height(Length::Dp(240.0));
let grid = Placed::new(Recycler::new(items).grid(2)).width(Length::MatchParent);
let pager = Placed::new(ViewPager::new(items).current_item(1))
    .width(Length::MatchParent)
    .height(Length::Dp(180.0));
```

`Recycler` uses `LinearLayoutManager`, or `GridLayoutManager` when `Recycler::grid` is set.
`ViewPager` configures orientation, offscreen-page limit, current item, and user input. The factory
receives `AdapterItemSizing::FillParent` for pager pages, because `ViewPager2` requires every page
to match its parent in both dimensions.

`MaterialCarousel` calls the same factory with `AdapterItemSizing::Carousel`. Carousel items must
match their parent in both dimensions and use a
`com.google.android.material.carousel.MaskableFrameLayout` as their root view; see
`example/android/app/src/main/java/com/example/krabik_ui_example/CarouselTextAdapter.java`.

## Development

Run the library tests from the repository root:

```bash
cargo test -p krabik-ui-android
cargo check -p krabik-ui-android
```

Build and run the example:

```bash
cd example/rust
RUST_ANDROID_ABIS="arm64-v8a" ./build-android.sh

cd ../android
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.example.krabik_ui_example/.MainActivity
```

The Gradle build runs `build-android.sh` automatically. Run the instrumented tests on a connected
device or emulator:

```bash
cd example/android
./gradlew :app:connectedDebugAndroidTest
```

See [`example/README.md`](example/README.md) for the example's architecture and testing details.
