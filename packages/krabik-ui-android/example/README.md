# krabik-ui-android example

A widget browser whose entire view hierarchy is built from Rust through direct JNI. It consumes
[`krabik-ui-android`](../) as a path dependency and mirrors the `rust/` + `android/` layout of a
project generated by [krabik](https://github.com/charafau/krabik).

The `AndroidBridge` Java class only loads the native library, hands the `Activity` and a click
listener to Rust, and forwards lifecycle events back into native code. There are no XML layouts,
Compose screens, WebViews, or custom renderers.

## What it shows

The main screen is a scrollable list with one button per supported widget. Tapping a button replaces
the content view with a demo screen for that widget. The demo's **Back** button and the system back
gesture both return to the list, restoring the list's previous scroll position.

```text
Main list (ScrollView → LinearLayout)
├── TextView   "Android widgets"
├── Button     "TextView"                  ──► TextView demo
├── Button     "Button"                    ──► Button demo (Rust-owned tap counter)
├── Button     "EditText"                  ──► EditText demo
├── ...
├── Button     "SearchView"                ──► SearchView demo
└── Button     "Toolbar"                   ──► Toolbar demo
```

`RecyclerView`, `ViewPager2`, and `AppCompatToolbar` come from AndroidX, and the Material demos come
from `com.google.android.material:material`. The app owns a small `TextRecyclerAdapter` Java class
because `RecyclerView.Adapter` is an abstract Java class that cannot be instantiated through JNI
alone.

The app uses the `Theme.Material3.DayNight.NoActionBar` theme and `MainActivity` extends
`AppCompatActivity`, so the Material date and time picker dialogs can use the support
`FragmentManager`. `CarouselTextAdapter.java` wraps carousel items in a `MaskableFrameLayout`, as
`CarouselLayoutManager` requires.

## Layout

```text
example/
├── rust/                    # Standalone app crate: krabik-ui-example
│   ├── src/android/         # Widget catalogue, screens, state, and JNI entry points
│   ├── build-android.sh     # Cross-compiles libkrabik_ui_example.so
│   └── Cargo.toml           # Path-depends on the library at ../..
└── android/                 # Gradle app shell
    ├── app/src/main/java/com/example/krabik_ui_example/
    │   ├── AndroidBridge.java
    │   ├── CarouselTextAdapter.java
    │   ├── MainActivity.kt
    │   ├── ScrollRestorer.java
    │   └── TextRecyclerAdapter.java
    └── app/src/androidTest/ # Espresso tests for the Rust-built UI
```

## Requirements

- Rust with the Android targets from `../rust-toolchain.toml` (installed automatically by rustup)
- Android SDK with an NDK installed under `$ANDROID_HOME/ndk` or pointed to by `ANDROID_NDK_HOME`
- JDK 17 or newer
- `adb` and a connected device or emulator

## Build and run

From `example/android`:

```bash
./gradlew :app:installDebug
```

The Gradle build invokes `example/rust/build-android.sh`, which compiles
`libkrabik_ui_example.so` for `arm64-v8a`, `armeabi-v7a`, `x86_64`, and `x86`, and stages the
libraries under `example/android/app/build/rustJniLibs/`. AGP packages them into the APK
automatically.

To build only one ABI while iterating:

```bash
cd example/rust
RUST_ANDROID_ABIS="arm64-v8a" ./build-android.sh
```

To use a different NDK or SDK location, set `ANDROID_NDK_HOME` or `ANDROID_HOME`. The build script
also reads `sdk.dir` from `example/android/local.properties`.

Useful diagnostics:

```bash
adb logcat -s RustUi
```

## Tests

```bash
# Library unit tests, from packages/krabik-ui-android
cargo test

# App crate compile check
cargo check --manifest-path example/rust/Cargo.toml

# Instrumented Android tests, on a connected device or emulator
cd example/android
./gradlew :app:connectedDebugAndroidTest
```

The instrumented tests exercise the real view hierarchy: they launch `MainActivity`, navigate from
the main list into widget and Material demos, return with both the in-app Back button and the system
back gesture, verify that the list keeps its scroll position, verify that the Rust-owned tap counter
updates its native `TextView`, and open a Material alert dialog.
