# krabik-ui-dsl widget showcase

A widget catalog whose entire UI is described by a standalone Rust crate and rendered as real
native views — UIKit on iOS, `android.widget` views on Android. It consumes
[`krabik-ui-dsl`](../) as a path dependency and mirrors the `rust/` + platform-shell layout of a
project generated by [krabik](https://github.com/charafau/krabik).

The home page lists every widget; each entry opens a page that demonstrates it in isolation. The
original checklist app is still there as one page. Navigation is application state (a `Page` enum
plus `page:*` actions), so the example does not depend on a future navigation primitive.

Each host only installs the app factory at startup and then hosts a `RustRootView`:

- **iOS** calls the C function `krabik_ui_dsl_example_install` and forwards lifecycle events.
- **Android** calls the JNI entry point `ExampleBridge.install`, which the example `cdylib`
  exports, and drives the view from `MainActivity`.

Both register the showcase through `set_app_factory`. There are no SwiftUI views, XML layouts,
WebViews, or custom renderers.

## Pages

```text
Home
├── Text & layout   Text · Button · Text field · Layouts
├── Inputs          Switch · Checkbox · Radio buttons · Radio group
├── Values          Slider · Progress · Spinner
├── Media           Image · Scroll view
├── Lists           Windowed list · Recycled list
└── Extras          Styling · Checklist
```

Highlights:

- **Radio group** — the group owns mutual exclusion and reports the selected index through
  `Event::Selected`.
- **Slider** — a continuous slider and a stepped one; the DSL quantizes the latter to multiples of
  ten before the app sees the value.
- **Progress** — a determinate bar driven by buttons and an indeterminate spinner.
- **Lists** — a windowed list that only materializes visible rows, and a native recycler with a
  tappable button in every row.
- **Checklist** — the original example, with switches, dynamic notes and per-row delete actions.

## Layout

```text
example/
├── rust/                    # Standalone app crate: krabik-ui-dsl-example
│   ├── src/lib.rs           # ShowcaseApp, Page navigation, events, FFI, unit tests
│   ├── src/pages.rs         # One builder per widget page
│   ├── src/checklist.rs     # The checklist page
│   └── Cargo.toml           # Path-depends on the DSL at ../../rust
├── ios/                     # Xcode app shell
│   ├── Sources/             # App entry, root view host, C declarations
│   ├── Resources/           # krabik.webp used by the Image page
│   ├── UITests/             # XCUITests for the Rust-built UI
│   └── KrabikUiDslExample.xcodeproj
└── android/                 # Gradle app shell
    ├── app/src/main/java/   # MainActivity and ExampleBridge
    ├── app/src/main/assets/ # krabik.webp used by the Image page
    ├── app/src/androidTest/ # Espresso tests for the Rust-built UI
    └── app/build.gradle.kts # Cross-compiles ../rust and wires the shared sources
```

Both Android shells in this package (this one, the two todo apps and the DSL's dev harness)
compile the Kotlin view layer from `../../shared/android/src/main/java` through a shared Gradle
source set, so `RustRootView`, `KrabikActivity` and the custom widgets exist once. Each shell's
`MainActivity` only loads its own native library and installs its app.

## Requirements

- Rust with the `aarch64-apple-ios-sim` target from `../../rust-toolchain.toml` (installed
  automatically by rustup)
- Xcode with an iOS simulator
- For Android: JDK 17, the Android SDK with `compileSdk = 37`, and an NDK (the Gradle build locates
  it via `ANDROID_NDK_HOME`, `ANDROID_NDK_ROOT`, or the SDK's `ndk/` directory)
- The `aarch64-linux-android` Rust target for the default `arm64-v8a` build

## Build and run: iOS

Build the static library, then build and run the Xcode project, which links it from
`../rust/target/…`:

```bash
cd rust
cargo build --target aarch64-apple-ios-sim
```

Then open `ios/KrabikUiDslExample.xcodeproj` in Xcode and run the `KrabikUiDslExample` scheme, or
from the command line:

```bash
cd ios
xcodebuild test -project KrabikUiDslExample.xcodeproj -scheme KrabikUiDslExample \
    -destination 'platform=iOS Simulator,name=iPhone 18 Pro'
```

## Build and run: Android

Gradle drives the whole flow. Every assemble that packages native libraries runs `cargo build` for
the selected ABIs first and copies the resulting `.so` files into `app/src/main/jniLibs`, so there
is no separate step to remember:

```bash
cd android
./gradlew :app:installDebug     # builds the Rust cdylib + Kotlin, then installs
./gradlew :app:assembleDebug    # APK only
```

The ABI defaults to the architecture of the machine running Gradle. Override it with
`-PkrabikAbis=arm64-v8a,x86_64` or the `KRABIK_ABIS` environment variable. The app installs as
`com.example.krabik_ui_dsl_example`, so it can coexist with the DSL's dev harness and the todo
examples.

## Tests

```bash
# State, navigation and checklist logic, from rust/
cargo test

# App crate lints, from rust/
cargo clippy --target aarch64-apple-ios-sim -- -D warnings
cargo clippy --target aarch64-linux-android -- -D warnings

# UI tests
#   iOS:     see the xcodebuild test command above
#   Android: ./gradlew :app:connectedDebugAndroidTest   (from android/)
```

The Rust tests cover navigation, the new widget state and the checklist delegation. The UI tests
drive the catalog itself:

- **Android** (`ShowcaseTest`, `ChecklistTest`, `LayoutTest`) opens the radio group, slider,
  progress, spinner, image and recycled-list pages, checks the indeterminate spinner and the
  windowed list, then runs the checklist flow and the frame-registry checks.
- **iOS** (`ShowcaseUITests`, `ChecklistUITests`) runs the same flow through XCUITest, including
  the radio-group selection, stepped slider, spinner and windowed list.

Both platforms include the checklist page, so the tests still cover per-row actions built at
runtime and in-place text updates.
