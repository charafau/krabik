# krabik-ui-dsl widget showcase

A widget catalog whose entire UI is described by a standalone Rust crate and rendered as real
native views — UIKit on iOS, `android.widget` views on Android. It consumes
[`krabik-ui-dsl`](../) as a path dependency and mirrors the `rust/` + platform-shell layout of a
project generated by [krabik](https://github.com/charafau/krabik).

The home page lists every widget; each entry opens a native navigation screen that demonstrates
it in isolation. The original checklist app is still there as one screen. The catalog is the
navigation root; `Msg::Open(key)` pushes a route and the platform's back action pops it. Each
screen is a `Scaffold` returned by `App::screen`: an app bar, a body and, on the Scaffold page, a
floating action button, a drawer and a snackbar. Dialog and bottom-sheet examples use
`App::dialog` and `App::sheet`. The palette is adaptive, so the app follows light and dark mode. The checklist screen is a child
component, mapped into the showcase's messages with `Element::map`.

Each host only installs the app factory at startup and then hosts the native session controller:

- **iOS** calls the C function `krabik_ui_dsl_example_install` and forwards lifecycle events.
- **Android** calls the JNI entry point `ExampleBridge.install`, which the example `cdylib`
  exports, and drives the view from `MainActivity`.

Both register the showcase through `set_app_factory`. There are no XML layouts,
WebViews, or custom renderers. The app uses one session with several native hosts: the main
catalog, navigation screens, and modal presentations.

## Pages

```text
Home
├── Text & layout   Text · Button · Text field · Layouts
├── Motion          Frames & opacity · Decoration · Enter & exit · Curves & springs · Page transitions
├── Containers      View pager · Tabs view · Bottom navigation · Toolbar
├── Inputs          Switch · Checkbox · Radio buttons · Radio group · Date picker · Tabs
├── Values          Slider · Progress · Spinner
├── Media           Image · Scroll view
├── Lists           Windowed list · Recycled list
└── Extras          Styling · Checklist · Dialog · Bottom sheet · Scaffold
```

Highlights:

- **Radio group** — the group owns mutual exclusion and reports the selected index through
  `on_select`.
- **Date picker** — date, time and date-and-time values with compact/inline modes and ranges.
- **Containers** — a swipeable pager, a tab strip synced to it, a native bottom navigation bar
  with custom icons, and host-level toolbar actions.
- **Motion** — implicit frame/opacity/decoration animations, enter/exit transitions, custom
  curves and native page transitions.
- **Slider** — a continuous slider and a stepped one; the DSL quantizes the latter to multiples of
  ten before the app sees the value.
- **Progress** — a determinate bar driven by buttons and an indeterminate spinner.
- **Lists** — a windowed list that only materializes visible rows, and a native recycler with a
  tappable button in every row. Shuffle opts into a 180 ms rebind cross-fade that never blocks
  holder reuse.
- **Image** — a bundled asset without an explicit height derives it from the image's aspect ratio;
  a disabled styled button shows how `.enabled(false)` dims DSL-drawn decoration.
- **Checklist** — the original example, with switches, dynamic notes and per-row delete actions.
- **Native navigation** — every widget page is a native screen. Rust owns the route stack through
  `App::navigation` / `screen`; the platform owns the app bar, transitions and back gesture.
- **Scaffold** — a floating action button that adds an item, a snackbar with Undo, and a
  navigation drawer that switches sections; Material controls on Android, a capsule button and
  two small custom views on iOS.
- **Dialog and Bottom sheet** — the dialog is the system alert built from a title, message and
  buttons; the bottom sheet is a native sheet around Rust-rendered content. Both report native
  dismissal as a message.

## Layout

```text
example/
├── rust/                    # Standalone app crate: krabik-ui-dsl-example
│   ├── src/lib.rs           # ShowcaseApp, Msg, update, navigation, FFI, unit tests
│   ├── src/pages.rs         # One builder per widget page
│   ├── src/checklist.rs     # The checklist screen, a child component
│   └── Cargo.toml           # Path-depends on the DSL at ../../rust
├── ios/                     # Xcode app shell
│   ├── Sources/             # App entry and the bridging header
│   ├── project.yml          # The project definition (XcodeGen)
│   ├── Resources/           # krabik.webp used by the Image page
│   ├── UITests/             # XCUITests for the Rust-built UI
│   └── KrabikUiDslExample.xcodeproj
└── android/                 # Gradle app shell
    ├── app/src/main/java/   # MainActivity and ExampleBridge
    ├── app/src/main/assets/ # krabik.webp used by the Image page
    ├── app/src/androidTest/ # Espresso tests for the Rust-built UI
    └── app/build.gradle.kts # Application id and dependencies
```

The shells contain almost nothing of their own. The Android apps in this package include the
Kotlin library in `../../shared/android` (`RustRootView`, `KrabikActivity`, the native widgets) as
the `:krabik-ui` module, and the iOS apps compile the Swift host in `../../shared/ios`. Each
`MainActivity` and App struct only loads its native library and installs its app.

## Requirements

- Rust with the `aarch64-apple-ios-sim` target from `../../rust-toolchain.toml` (installed
  automatically by rustup)
- Xcode with an iOS simulator
- For Android: JDK 17, the Android SDK with `compileSdk = 37`, and an NDK (the Gradle build locates
  it via `ANDROID_NDK_HOME`, `ANDROID_NDK_ROOT`, or the SDK's `ndk/` directory)
- The `aarch64-linux-android` Rust target for the default `arm64-v8a` build

## Build and run: iOS

The Xcode project builds the Rust static library itself in a build phase.
Open `ios/KrabikUiDslExample.xcodeproj` in Xcode and run the `KrabikUiDslExample` scheme, or
from the command line:

```bash
cd ios
xcodebuild test -project KrabikUiDslExample.xcodeproj -scheme KrabikUiDslExample \
    -destination 'platform=iOS Simulator,name=iPhone 17'
```

The project is generated from `ios/project.yml`; run `xcodegen generate` in `ios/` after editing
it.

## Build and run: Android

Gradle drives the whole flow. Every assemble that packages native libraries runs `cargo build` for
the selected ABIs first and copies the resulting `.so` files into `app/src/main/jniLibs`, so there
is no separate step to remember:

```bash
cd android
./gradlew :app:installDebug     # builds the Rust cdylib + Kotlin, then installs
./gradlew :app:assembleDebug    # APK only
```

The ABI defaults to the architecture of the machine running Gradle. Override it with
`-PkrabikAbis=arm64-v8a,x86_64` or the `KRABIK_ABIS` environment variable. The app installs as
`com.example.krabik_ui_dsl_example`, so it can coexist with the DSL's dev harness and the todo
examples.

## Tests

```bash
# State, navigation and checklist logic, from rust/
cargo test

# App crate lints, from rust/
cargo clippy --target aarch64-apple-ios-sim -- -D warnings
cargo clippy --target aarch64-linux-android -- -D warnings

# UI tests
#   iOS:     see the xcodebuild test command above
#   Android: ./gradlew :app:connectedDebugAndroidTest   (from android/)
```

The Rust tests cover navigation, the dialog and sheet, widget state and the checklist component. The
UI tests drive the catalog and the native hosts:

- **Android** (`ShowcaseTest`, `ChecklistTest`, `LayoutTest`) opens the radio group, slider,
  date picker, tabs, the four animation pages, page transitions, the four container pages,
  progress, spinner, image and recycled-list pages, checks the indeterminate spinner, the windowed list and system back, then
  opens a dialog and the bottom sheet, exercises the Scaffold page, rotates the device, switches
  to dark mode, and runs the checklist flow and the frame-registry checks.
- **iOS** (`ShowcaseUITests`, `ChecklistUITests`) runs the same flow through XCUITest, including
  the radio-group selection, stepped slider, date picker kinds, tab selection, the animation
  pages, page transitions, spinner, windowed list, the Scaffold page and the switch to dark mode.

Both platforms include the checklist page, so the tests still cover per-row messages and
in-place text updates.
