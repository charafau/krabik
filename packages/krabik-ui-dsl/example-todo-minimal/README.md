# krabik-ui-dsl minimal todo

The smallest useful todo app built with [`krabik-ui-dsl`](../): a standalone Rust crate rendered as
real native views — UIKit on iOS, `android.widget` views on Android. It keeps only the core flow
and mirrors the `rust/` + platform-shell layout of a project generated by
[krabik](https://github.com/charafau/krabik).

Its views are written with the [`view!`](../docs/tutorial/08-the-view-macro.md) macro, which is
only a shorter way to write the builder calls the other examples use.

The full widget tour (filters, slider, progress, sorting and switches) lives in the sibling
[`example-todo`](../example-todo) app.

Each host only installs the app factory at startup and then hosts a `RustRootView`:

- **iOS** calls the C function `krabik_ui_dsl_todo_minimal_install` and forwards lifecycle events.
- **Android** calls the JNI entry point `MinimalTodoBridge.install`, which the example `cdylib`
  exports, and drives the view from `MainActivity`.

Both register the app through `set_app_factory`. There are no SwiftUI views, XML layouts, WebViews,
or custom renderers.

## What it shows

Only the core todo loop, with no extra widgets:

- **Text field and Add button** — `TextChanged` and `Submitted` (return key) events append a task.
- **Checkbox rows** — `Toggled` events mark a todo done, recolor the row and update the summary.
- **Recycled list** — `List::recycled()` with a fixed row height and a keyed row builder, so only
  the visible rows exist as native views.
- **Per-row delete and Clear completed** — `Click` actions remove one row or all done rows.

```text
Column
├── Text            "Todo"
├── Text            "1 of 4 done"
├── Row             TextField "What needs doing?" + Button "Add"
├── Row             Button "Clear completed"
└── List (recycled)
    └── Row         Checkbox + Button "Delete"   (one per todo)
```

## Layout

```text
example-todo-minimal/
├── rust/                    # Standalone app crate: krabik-ui-dsl-todo-minimal
│   ├── src/lib.rs           # Todo app, state, events, factory install, unit tests
│   └── Cargo.toml           # Path-depends on the DSL at ../../rust
├── ios/                     # Xcode app shell
│   ├── Sources/             # App entry, root view host, C declarations
│   ├── UITests/             # XCUITest for the Rust-built UI
│   ├── project.yml          # xcodegen spec for KrabikUiDslTodoMinimal.xcodeproj
│   └── KrabikUiDslTodoMinimal.xcodeproj
└── android/                 # Gradle app shell
    ├── app/src/main/java/   # MainActivity and MinimalTodoBridge
    ├── app/src/androidTest/ # Espresso test for the Rust-built UI
    └── app/build.gradle.kts # Application id and dependencies
```

The shells contain almost nothing of their own. The Android app includes the Kotlin library in
`../../shared/android` (`RustRootView`, `KrabikActivity`, the native widgets) as the `:krabik-ui`
module, and the iOS app compiles the Swift host in `../../shared/ios`. `MainActivity` and the App
struct only load the native library and install the app.

## Requirements

- Rust with the `aarch64-apple-ios-sim` target from `../../rust-toolchain.toml` (installed
  automatically by rustup)
- Xcode with an iOS simulator, plus [xcodegen](https://github.com/yonaskolb/XcodeGen) if you change
  `ios/project.yml`
- For Android: JDK 17, the Android SDK with `compileSdk = 37`, and an NDK (the Gradle build locates
  it via `ANDROID_NDK_HOME`, `ANDROID_NDK_ROOT`, or the SDK's `ndk/` directory)
- The `aarch64-linux-android` Rust target for the default `arm64-v8a` build

## Build and run: iOS

The Xcode project builds the Rust static library itself in a build phase.

Open `ios/KrabikUiDslTodoMinimal.xcodeproj` in Xcode and run the `KrabikUiDslTodoMinimal`
scheme, or from the command line:

```bash
cd ios
xcodebuild test -project KrabikUiDslTodoMinimal.xcodeproj -scheme KrabikUiDslTodoMinimal \
    -destination 'platform=iOS Simulator,name=iPhone 17'
```

If you edit `project.yml`, regenerate the project with `xcodegen generate` from `ios/`.

## Build and run: Android

Gradle drives the whole flow. Every assemble that packages native libraries runs `cargo build` for
the selected ABIs first and copies the resulting `.so` files into `app/build/rustJniLibs`, so there
is no separate step to remember:

```bash
cd android
./gradlew :app:installDebug     # builds the Rust cdylib + Kotlin, then installs
./gradlew :app:assembleDebug    # APK only
```

The ABI defaults to the architecture of the machine running Gradle. Override it with
`-PkrabikAbis=arm64-v8a,x86_64` or the `KRABIK_ABIS` environment variable. The app installs as
`com.example.krabik_ui_dsl_todo_minimal`, so it can coexist with the DSL's dev harness and the
showcase app.

## Tests

```bash
# State and event logic, from rust/
cargo test

# App crate lints, from rust/
cargo clippy --target aarch64-apple-ios-sim -- -D warnings
cargo clippy --target aarch64-linux-android -- -D warnings

# UI tests
#   iOS:     see the xcodebuild test command above
#   Android: ./gradlew :app:connectedDebugAndroidTest   (from android/)
```

The Rust tests cover trimming new titles, toggling, per-row deletion and clearing completed tasks.
The iOS and Android UI tests drive the same flow through the real native widgets: complete a row,
add a task through the text field, and clear the completed rows.
