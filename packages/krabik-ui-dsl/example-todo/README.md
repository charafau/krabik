# krabik-ui-dsl todo showcase

A todo app whose entire view tree is described by a standalone Rust crate and rendered as real
native views — UIKit on iOS, `android.widget` views on Android. It consumes
[`krabik-ui-dsl`](../) as a path dependency and mirrors the `rust/` + platform-shell layout of a
project generated by [krabik](https://github.com/charafau/krabik).

The companion [`example-todo-minimal`](../example-todo-minimal) keeps only the core add/complete
flow; this app is the full widget tour.

Each host only installs the app factory at startup and then hosts a `RustRootView`:

- **iOS** calls the C function `krabik_ui_dsl_todo_install` and forwards lifecycle events.
- **Android** calls the JNI entry point `TodoBridge.install`, which the example `cdylib` exports,
  and drives the view from `MainActivity`.

Both register the app through `set_app_factory`. There are no SwiftUI views, XML layouts, WebViews,
or custom renderers.

## What it shows

The showcase exercises the current widget set and the events they produce:

- **Checkbox rows** — `Toggled` events toggle a todo and update the summary and progress bar.
- **Radio buttons** — `All` / `Active` / `Done` filters rebuild the visible rows.
- **Slider** — sets the priority (1–5) of newly added tasks and updates its own label.
- **Progress indicator** — tracks the completed fraction of all tasks.
- **Switch** — sorts the list by priority instead of insertion order.
- **Recycled list** — `List::recycled()` with a fixed row height and a keyed row builder, so only
  the visible rows exist as native views.
- **Text field and buttons** — `TextChanged`, `Submitted` (return key) and `Click` events for
  adding, deleting a row and clearing completed tasks.

```text
Column
├── Text            "Todo"
├── Text            "1 of 4 done"
├── ProgressIndicator
├── Row             RadioButton "All" · "Active" · "Done"
├── Row             TextField "What needs doing?" + Button "Add"
├── Row             Text "Priority: 3" + Slider
├── Row             Text "Sort by priority" + Switch
├── Row             Button "Clear completed"
└── List (recycled)
    └── Row         Checkbox + Text "P4" + Button "Delete"   (one per visible todo)
```

## Layout

```text
example-todo/
├── rust/                    # Standalone app crate: krabik-ui-dsl-todo
│   ├── src/lib.rs           # Todo app, state, events, factory install, unit tests
│   └── Cargo.toml           # Path-depends on the DSL at ../../rust
├── ios/                     # Xcode app shell
│   ├── Sources/             # App entry, root view host, C declarations
│   ├── UITests/             # XCUITest for the Rust-built UI
│   ├── project.yml          # xcodegen spec for KrabikUiDslTodo.xcodeproj
│   └── KrabikUiDslTodo.xcodeproj
└── android/                 # Gradle app shell
    ├── app/src/main/java/   # MainActivity and TodoBridge
    ├── app/src/androidTest/ # Espresso test for the Rust-built UI
    └── app/build.gradle.kts # Application id and dependencies
```

The shells contain almost nothing of their own. The Android app includes the Kotlin library in
`../../shared/android` (`RustRootView`, `KrabikActivity`, the native widgets) as the `:krabik-ui`
module, and the iOS app compiles the Swift host in `../../shared/ios`. `MainActivity` and the App
struct only load the native library and install the app.

## Requirements

- Rust with the `aarch64-apple-ios-sim` target from `../../rust-toolchain.toml` (installed
  automatically by rustup)
- Xcode with an iOS simulator, plus [xcodegen](https://github.com/yonaskolb/XcodeGen) if you change
  `ios/project.yml`
- For Android: JDK 17, the Android SDK with `compileSdk = 37`, and an NDK (the Gradle build locates
  it via `ANDROID_NDK_HOME`, `ANDROID_NDK_ROOT`, or the SDK's `ndk/` directory)
- The `aarch64-linux-android` Rust target for the default `arm64-v8a` build

## Build and run: iOS

The Xcode project builds the Rust static library itself in a build phase.

Open `ios/KrabikUiDslTodo.xcodeproj` in Xcode and run the `KrabikUiDslTodo` scheme, or from the
command line:

```bash
cd ios
xcodebuild test -project KrabikUiDslTodo.xcodeproj -scheme KrabikUiDslTodo \
    -destination 'platform=iOS Simulator,name=iPhone 17'
```

If you edit `project.yml`, regenerate the project with `xcodegen generate` from `ios/`.

## Build and run: Android

Gradle drives the whole flow. Every assemble that packages native libraries runs `cargo build` for
the selected ABIs first and copies the resulting `.so` files into `app/build/rustJniLibs`, so there
is no separate step to remember:

```bash
cd android
./gradlew :app:installDebug     # builds the Rust cdylib + Kotlin, then installs
./gradlew :app:assembleDebug    # APK only
```

The ABI defaults to the architecture of the machine running Gradle. Override it with
`-PkrabikAbis=arm64-v8a,x86_64` or the `KRABIK_ABIS` environment variable. The app installs as
`com.example.krabik_ui_dsl_todo`, so it can coexist with the DSL's dev harness and the minimal app.

## Tests

```bash
# State and event logic, from rust/
cargo test

# App crate lints, from rust/
cargo clippy --target aarch64-apple-ios-sim -- -D warnings
cargo clippy --target aarch64-linux-android -- -D warnings

# UI tests
#   iOS:     see the xcodebuild test command above
#   Android: ./gradlew :app:connectedDebugAndroidTest   (from android/)
```

The Rust tests cover the state transitions directly: trimming new titles, snapping the slider
priority, filtering, priority sorting, deletion and clearing completed tasks.

The iOS UI test drives the real view hierarchy: it completes a row, adds a task through the native
text field, switches filters, drags the slider to priority 5, adds a high-priority task and clears
the completed rows. The Android Espresso test performs the same flow through the native widgets.
Per-row deletion is covered by the Rust state tests rather than Espresso, because RecyclerView
rebinds rows while the assertion runs.
